依頼の理解（三行）

  • 山波創苑専用の外構・造園CADを、Obsidian の非公開プラグイン（Windows と iPhone で同じもの）として段階的に作る。2Dの図が唯一の正本で、3D・数量・見積・出力はそこから生まれ、図面・写真・台帳は vault に置いて Obsidian Sync で運ぶ。
  • 部材カタログの物量では競わない。操作の軽さ、石・植栽・地形の細かさ、施主に見せる絵の質、寒冷高地と傾斜地の条件で勝つ。地域の数値は根拠を確かめてから既定値にする。
  • 各段は「提案→裁可→実装→受け入れ確認→山彦班点検」。次は仕様の確定→iPhone 実機での試作計測→第一段。本番の vault では試さず、作業が消えないことを最優先にする。

今回の質問

試験用の vault を、PC と iPhone の間でどう運びますか。

詰まっている点：Obsidian Sync の Standard で同期できる vault は一つ（Plus は十）で、その一つは YAMANAMI-BRAIN が使っています。一方、約束では本番の vault で試しません。このままでは、試作を iPhone の試験用 vault へ届ける道がありません。（出典：Obsidian Help「Plans and storage limits」）

一

開発の間だけ Plus に上げる

推奨
仕組み
Plus にして、試験用 vault を二つ目の同期先として PC と iPhone につなぐ。プラグインは本番と同じく「インストール済みプラグインの同期」で iPhone に届く。
良い点
本番と同じ道で試せる。描画の重さだけでなく、同期の受け入れ基準（スマホで描いた図が PC で欠けずに開けるか、競合しても消えないか）を、本番に触れずに毎段確かめられる。晃さんの手順は「三つのファイルを PC の試験用 vault に置く」だけ。
弱い点
月額の差額がかかる（金額は公式の料金表で確かめてください）。上限が緩いので Standard の 5MB を超えても同期では気づけない。これはプラグイン自身が Standard の上限を物差しに容量を測って知らせる作りで補い、本番へ入れる前に Standard の条件で一度確かめる。Standard に戻すときは試験用の同期先を片づけてから戻す。
二

費用をかけず、iPhone へは補助プラグインで届ける

仕組み
iPhone に端末の中だけの試験用 vault を作り、GitHub からプラグインを取り込む補助プラグイン（BRAT）を入れる。私が GitHub に置いた版を、iPhone が直接取りに行く。
良い点
費用なし。PC を経由せずに iPhone の版を更新できる。
弱い点
図面は PC と iPhone の間で運べないので、描画の重さは測れても、同期の受け入れ基準は試せない（その試験を後で Plus にして行うか、本番で行うかの判断が残る）。非公開のリポジトリなので、iPhone の BRAT に GitHub の読み取り用の鍵を入れる必要がある。試験用 vault に、本番にない補助プラグインが一つ増える。

外した案：本番 vault の中に試験用フォルダを作る（本番で試さない約束に反する）。iCloud Drive に試験用 vault を置く（三つ目の同期が加わり、二重同期の問題を増やす）。iPhone の「ファイル」アプリで手で入れる（プラグインの置き場所 .obsidian は「ファイル」アプリに表示されない）。

「一」か「二」でお答えください。一の場合、Plus への切り替えと二つ目の同期先の作り方は、次の回で画面の順に書きます。
